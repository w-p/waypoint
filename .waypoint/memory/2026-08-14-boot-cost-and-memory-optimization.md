- **2026-08-14:** Shipped the boot/memory optimization — a smaller mandatory session boot and a filename-as-index memory convention. Design and plan dated 2026-08-07 (`.waypoint/design/2026-08-07-cost-curve-and-document-model.md`, `.waypoint/plan/2026-08-07-cost-curve-and-document-model.md`).

  **The problem.** Waypoint's cost grows with project age: the phase gate keeps adding documents (design → plan → features), and OPORD §3a told the agent to read everything relevant to the phase every session, so boot cost = the running sum of everything ever produced. A downstream project reported a ~26k boot; ours was ~9.7k with empty design/plan folders — the same curve, earlier on it.

  **Key reframes that shaped the fix** (worth keeping — they killed two rabbit holes):
  - *Caching changes the target.* Boot docs sit at the front of context and read at ~0.1x once cached, so a big boot isn't mainly a per-turn dollar cost — its real harm is eating context budget (→ earlier compaction, where fidelity dies) and being re-paid cold on every fresh session. So shrinking the boot and preserving fidelity are the same goal, not a tradeoff.
  - *Map, not taxonomy.* We explored classifying memory files (feature/bug/chore, magnitude) and a curated "current focus" field. Rejected both: a taxonomy is a schema to learn (against the "just Markdown" ethos) and magnitude doesn't predict relevance (a one-line change can carry a binding decision). The `YYYY-MM-DD-<slug>` filename convention is *already* a complete, free index — the only bug was §3a said "read the files" instead of "read the list, open what's needed."

  1. Drift test in `test.sh` — asserts `templates/opord.md` ≡ `.waypoint/opord.md` and `templates/memory.md` ≡ `.waypoint/memory/README.md`. Guards the dogfooding invariant. 54 tests pass (was 52).
