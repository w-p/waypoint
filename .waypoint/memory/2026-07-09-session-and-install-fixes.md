- **2026-07-09:** Addressed four operational issues found while using Waypoint.
  1. **Session startup** — adapters no longer force `"Ready."`. Both the Claude (`adapters/claude/rules/waypoint.md`) and Cursor (`adapters/cursor/rules/session-briefing.mdc`) briefings now say: come up to speed silently, then if the first message has a real request, note "Coming up to speed…" and answer it; if it's just an opener, reply `"Ready."` No document summaries or meta-commentary either way.
  2. **Permission prompts** — OPORD §3c/§5 previously imposed a second approval gate ("do not run CLI/commit unless explicitly approved") that fought the host tool's own permission system and caused re-prompting after the user had granted permission. Rewrote §3c to defer to the host's permission model (a granted permission is authoritative) and reserve in-band confirmation for genuinely consequential/irreversible actions; §5 aligned.
  3. **Merge conflicts** — `.waypoint/memory.md` (single append-file) → `.waypoint/memory/` folder, one file per session named `YYYY-MM-DD-<slug>.md`. Chose date+slug over host session-id (portable, sorts chronologically, human-readable). `templates/memory.md` is now the folder's convention README. `project.md` stays single (living index, not an append log); design/plan/features/skills were already per-item folders. Updated all six skills, OPORD, README, and this repo's own dogfooded `.waypoint/`.
  4. **Install/update process** — extracted all install logic from the Makefile into a readable `bin/waypoint` shell script (Makefile is now a thin dispatcher). **Claude adapter is a standalone rule file at `.claude/rules/waypoint.md`** — the mirror of Cursor's `.cursor/rules/session-briefing.mdc`. Both adapters are now plain wholesale file copies; there is no marker/merge machinery and Waypoint never edits the project's own `CLAUDE.md`. `update` migrates `memory.md`→`memory/`, relocates any legacy embedded `CLAUDE.md` briefing block to the rule file (and flags the old block for manual removal), refreshes skills + adapter, and reports OPORD drift. **OPORD is manual-merge on update** (user's decision): `update` never rewrites `.waypoint/opord.md`; it prints a `diff` against the shipped baseline to merge by hand. Verified fresh install, install-into-existing-CLAUDE.md, legacy→update migration, idempotency, drift notice, and cursor auto-detect against temp dirs.
  - **Fact corrected (I was wrong first):** Claude Code loads project instructions from *either* `./CLAUDE.md` *or* `./.claude/CLAUDE.md`, and loads `.claude/rules/*.md` (no `paths` frontmatter) every session at the same priority.
